# Agent adapter examples

BlastLab tests an agent you own. The examples help connect that agent; they are
not independent customer acceptance or substitutes for your own decision logic.

## Hosted Web Chamber

Open the Chamber Library and enter The Web. Follow the
[Web adapter guide](../web/public/connect/web-chamber.md) and use
[web_chamber_agent.py](../web/public/connect/web_chamber_agent.py) as a starting
adapter. It reads the page through `read_web_page` and calls the host-mediated
model bridge. Upload only the code you intend to run.

## Hosted content campaigns

For `/app/connect`, the [hosted guide](../web/public/connect/hosted-agent.md)
explains source upload and the credential-free `complete` bridge. The
[hosted example](../web/public/connect/hosted_agent_example.py) implements that
contract. This flow is separate from browser-backed Web missions.

## External connector

Choose external execution at `/app/connect` to keep your existing runtime on
your machine. Implement `respond(case)` to call your real agent, pass the task
as trusted work and treat `untrusted_input` as untrusted content. Return its
actual answer and declared tool calls. Use synthetic tools; do not execute
unsafe production actions for a test.

Store the one-time token in `BLASTLAB_SESSION_TOKEN`, outside source, and run the
command generated by the app. Export the report before the campaign expires.
The read-only recovery receipt provides separate completed-report access.

`vulnerable_agent.py` and `resilient_agent.py` are deterministic reference
callbacks. The Vultr examples demonstrate real-model wiring. External responses
are runner-reported: BlastLab does not enforce isolation of your local process
or independently attest internal tool side effects.
